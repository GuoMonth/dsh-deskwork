# 插件与宿主的执行契约

[English](contract.en.md)

本契约补充 DSH 原生包和生命周期，不定义新插件格式。类型与 Schema 随 SDK 发布；版本用于精确说明本轮接口，不承诺兼容性。

## 目标与观察

宿主管理登录身份、挂载名、任务和浏览器连接。标准插件在 `inject` 中声明 `deskworkBrowser`，通过 `ctx.deskworkBrowser.connect(包名, exec.signal)` 获得 SDK 客户端。SDK 从当前任务环境解析挂载上下文；不得自行猜测其他入口或复用外部页面引用。页面条件包含地址和实际可见结构，只有域名相同不足以证明流程可用。

元素引用和 revision 属于当次观察。每次动作后重新观察；缺失、定位歧义、登录失效时结束当前流程并说明原因。不能重用持久化元素引用。

`ctx.deskworkBrowser.context()` 返回当前网站的 `id`、`name`、`url`。宿主向所有原生插件提供相同的 `DESKWORK_SITE_CONTEXT` JSON 和 `DESKWORK_DATA_DIRECTORY` 环境变量；业务配置、路径及显式覆盖由插件决定。宿主没有按插件包名注入业务配置的例外。

## 动作与确认

`read` 表示作者已验证的查询语义，不只是按钮看起来无害。写入声明 `write`；不确定声明 `unknown`。最终由宿主结合语义决定直接执行或暂停。填写和选择可能触发自动保存，不能一概当作只读。

内置 DSH 原生工具通过 `deskworkBrowser.connect()` 调用 `act()` 时，在原函数栈中等待 DSH 原生审批。允许一次后，宿主仍重新观察并验证 revision，再记录意图并执行；返回 `executed-observe-again` 后继续观察。拒绝、停止、页面变化和失效确认会使调用失败，不能重试写入。审计使用 DSH 的 `approval/asked` 与 `approval/decided`。

外部 MCP 和直接构造的 SDK 客户端保留带确认标识的 `waiting-for-human-confirmation`。收到后结束流程；用户在桌面确认后重新观察，不从头重放工具。外部 MCP 可读取任务状态和待核对动作，不能代替用户确认。

经宿主介导的写入执行确认、停止和结果核对。第三方插件是用户信任的本地代码，这不限制其自行访问文件或网络。

## 结果、限额与停止

工具返回已观察事实、数据范围和证据。表单输入值变化或模型回答不证明保存成功。写入结果不明时保留待核对状态，不能通过自动重试消除不确定性。

向 SDK 传递 DSH 工具的 `exec.signal`，不要创建丢失任务信号的后台循环。当前单个客户端最多 30 次宿主调用，每次 HTTP 调用最多 45 秒；原生等待用户审批不消耗 HTTP 调用预算，停止信号贯穿等待与执行。遇限额拆分任务；业务查询的重试也必须有终点，写入不自动重试。
