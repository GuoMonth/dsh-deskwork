# 产品与工程原则

## 固定业务环境，长期积累能力

目标用户长期操作少量固定 ERP。启动配置预置系统入口，用户自行登录；Copilot 和 Agent 共用连接、任务和技能。业务会话和模型会话分别管理。

「多数功能多年稳定」是来自产品讨论的目标场景假设，需要在具体客户系统验证。稳定的操作路径仍然处理实时变化的业务数据、身份和单据状态。

## AI 组织任务，已验证的工具执行重复步骤

AI 理解目标、组合技能并处理异常；熟悉的操作优先复用验证过的浏览器脚本、业务 API 或 MCP 工具。技能需要输入输出、适用条件和结果判据，长任务需要进度与恢复语义。

## 本地经验有生命周期

基础技能可随客户端分发；学习成果放在独立的用户数据目录，升级时保留，并考虑备份和迁移。技能与凭据分开。客户端存储不等于模型必须本地运行。

候选经验经过业务结果验证后才能成为默认能力；记录适用范围、版本和效果，支持失效识别、局部修复与回滚。一次成功或重复播放脚本不能证明自主学习。

## AI coding / AI friendly first

让人和 AI 都能通过清晰的目录、类型、命名、状态和可运行测试定位问题。优先缩小理解范围、让错误在编译期或边界暴露，并保持全仓一致。

文档驱动记录原则、设计与讨论决策；测试驱动表达可观察行为。代码应当自解释，注释只补充代码无法表达的原因、外部约束或反直觉取舍。

## 用证据选择架构

Electron、DSH、Browser Harness 是候选组合。先写可证伪判据，再做有边界的实验；结果仅覆盖测试过的环境。不因宣传、Star 数、示例成功或个人熟悉程度宣布方案成熟。

本地优先承担浏览器、性能和兼容性实验。GitHub CI 提供可复现的共同检查入口，不代替本地证据。
