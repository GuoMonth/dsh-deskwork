# 通用工作台 MVP 验证 · 2026-09-06

源码身份：本记录所在提交，分支 `feat/m1-senguo-workspace`，PR #2。依赖沿用锁文件：Electron 44.2.0、DSH 0.1.2-rc.1、Node 24。Linux x64 实验在 Xvfb 与已授权 host 隔离环境运行；产品仍保留 Chromium sandbox。

## 结论与覆盖

两个结构不同的网站仅通过配置接入，同一套浏览器工具与真实 DSH 进程完成观察、填写提议、确认、提交、刷新回读。产品没有这两个站点的选择器、对象类型或字段映射。模型是独立本地 SSE 夹具；它根据当次工具观察生成动作，不能代替真实 DeepSeek 的质量验证。

本轮修正过两个验证问题：测试网站的会话 Cookie 未设置有效期，不能证明重启保留登录，改为明确的持久 Cookie；Playwright 的 DOM 填写不能代表 Electron 原生用户输入，接手回归改用原生输入事件。不会把这些结果推广成所有 ERP 登录策略都兼容。

Electron `BrowserWindow.capturePage()` 在本环境的截图不包含 WebContentsView 网页层。系统屏幕捕获证明实际网页正常显示；因此同时保留外壳、网页和系统截图，不把空白截图误认为网页未加载。测试直接断言原生 View 的可见性和尺寸。

## 已知限制

- 真实 DeepSeek API 密钥当前不可用；真实模型完成率、耗时、已登录森果业务及用户 Mac 安装验收仍待完成。
- 通用操作目前覆盖普通 DOM。跨域 iframe、封闭 Shadow DOM、canvas、复杂自定义控件、上传下载及通用 SSO 未验收；不自动转为 ERP 专属连接器。
- 观察输出有数量与长度限制；密码不作为字段值输出，长字段和未知控件需接手。截图不用于含可见密码框的登录页面。
- 未验证的填写、选择、未知按钮、关键按键和带查询参数的导航先确认。普通链接的判断是已知语义规则，不证明任意网页脚本没有隐藏副作用。
- 自动结果核对只覆盖确认卡片中的明确文本判据：操作前未出现、刷新后在同一 URL 正文出现。不能独立验证时用户核对；模型完成文本不是成功证据。
- 身份变化通过浏览器会话和 Cookie 变化等可观察信号处理；不宣称理解所有网站内部账号切换机制。

本地 `npm run check` 的格式、链接、类型、typed lint 与 21 项确定性测试通过；Linux 安装目录通过 `xvfb-run -a node scripts/verify-package.ts` 的真实运行时与双站点检查。macOS 使用同一脚本验证发行包，具体 CI 结果见 PR。

原始输出位于 `.artifacts/m1-*.log`、`.artifacts/desktop/evidence.json`、`.artifacts/configured-site/`；不包含真实模型密钥或已登录业务数据。macOS CI、发行包验证和下载链接随本 PR 更新，未完成的真实验收不标为通过。
