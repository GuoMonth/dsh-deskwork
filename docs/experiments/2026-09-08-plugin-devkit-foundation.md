# M3 开发套件骨架验证

环境：Linux、Node 24，沿用本地已授权开发账号。未使用网站身份或真实模型，不写入业务数据。

## 已验证

- SDK 浏览器类型／Schema 提取后，宿主与 SDK 共用定义。既有原生插件通过真实 DSH 运行时加载与查询回归。
- 两个标准 npm 包在系统临时目录安装；MCP stdio 在无 Deskwork 连接和业务凭据的环境中启动，五个 Resources 均可读取，工具读取／关键词搜索有效，非法文档 ID 被拒绝后仍能继续服务。
- 从打包后的模板创建独立项目，已有目录拒绝覆盖。安装依赖后严格 TypeScript 编译、生成运行文件及 `npm pack` 通过；产物依赖公开 SDK，不解析仓库内部源码。
- 开发 Skill 格式校验通过。文件、MCP 和原生 DSH 模块共用指南。原生开发模块已编译；本轮未单独验证其经市场安装后的 Skill 调用，不据此宣称默认内置或市场可用。
- `npm run check` 完成格式、文档、类型、lint 和现有行为回归；`npm run test:devkit` 提供可复现的仓库外安装检查并接入 CI。

## 实际发现

模板最初依赖 `dsh-tools` 后，在仓库外严格编译失败：上游间接类型引用 `dsh-attachment`，仓库依赖曾掩盖此缺项。模板显式添加本轮版本的开发依赖后通过，没有使用 `skipLibCheck` 绕过。
