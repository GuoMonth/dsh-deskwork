# M2：原生 Skill 资产包与查询提速

状态：**开发计划草案，待审阅；尚未实施。** 基于 `alpha.2`。用户已反馈本地测试效果符合当前预期；该反馈作为继续迭代的依据，不推定所有 M1 真实业务写入场景已验收。

## 目标

完成「外部高能力 AI 熟悉一个 ERP 菜单域 → 制作知识资产 ZIP → Deskwork 导入并绑定网站 → 普通模型按需加载 → 连续查询 → 核对结果」闭环。

已验证只读操作连续执行，业务写入前确认。包是可选加速能力，网站仍只需网址即可接入。品牌、业务对象和选择器不进入工作台通用内核。

## 范围与取舍

- 复用已固定的 DSH `0.1.2-rc.1`、Electron、React、严格 TypeScript、Node/npm 与现有桌面热重载；除非验证发现阻塞，不升级或替换运行时。
- 优先组合 `dsh-skill`、`dsh-skill-filesystem` 和 `dsh-tool-skill`；复用目录、按需正文加载、缓存及 Cordis 生命周期。原生提供器不能满足网站隔离或版本固定时，仅适配提供器，不另建技能注册引擎。
- 本轮资产以 Skill 指令、知识关系和声明式流程数据组成，不安装任意第三方可执行插件，不恢复模型任意 JavaScript／shell 权限。浏览器动作继续经过宿主执行控制。
- ZIP 为离线交付载体，内容优先兼容 DSH Skill 目录。Deskwork 元数据仅表达包版本、适用网站／页面、输入输出、动作影响、结果判据与兼容要求；精确字段由接入验证确定。
- 高能力 AI 在外部制作首个包并保留验证依据；桌面侧普通模型负责选择、参数化、异常处理。客户端自动探索、自动修复、自动晋升和双模型调度后移。
- 不建设市场。社区 DSH 市场作为后续发现／分发来源；Web 市场 UI、pnpm 安装链路和桌面兼容性需单独评估。
- PC 优先，仅交付 macOS Apple Silicon DMG。保持当前临时签名和公证边界，不在本轮扩大分发范围。

## 三个连续阶段

### 1. 原生接入验证与确认策略

先在本地热重载实例验证最小链路，再定包协议：

- 在 `sdk-minimal` 中启用原生技能组件；一个外部技能的摘要可见、正文按需读取，引用的知识附件也能在受限范围内读取。
- 只暴露当前任务所绑定网站的技能目录；不扫描用户其他项目／全局技能。验证两网站、重名、卸载后新任务不可使用及重启恢复。
- 通过生命周期实测决定挂载在任务边界切换还是可安全动态切换，不宣称“文件监听”天然等于任务级升级安全。
- 将动作影响区分为已验证只读、业务写入和未知；将“需要确认”与“写入结果待核对”分开。已确认的只读菜单跳转不再自动产生写入待核对状态。
- 无包时可可靠识别的只读操作继续直接执行；已验证知识补充自定义查询按钮和筛选控件的语义。模型声明或按钮名称不能单独证明没有副作用。
- 沿用一份查询任务记录基线，分开模型时间、浏览器执行／观察时间、人工等待；不新增性能平台。

退出条件：真实 DSH + 真实 Electron + 外部 Skill 的最小查询跑通；只读直行、写入拦截、未知暂停三个分支有明确证据。原生接入失败先记录具体缺口和最小替代方案，不自动改建自有插件平台。

### 2. 资产包管理与受控流程复用

- 提供通用「资产包」入口：导入 ZIP、查看版本和适用范围、填写唯一挂载名、绑定网站、取消挂载、升级替换及删除未使用版本。
- ZIP 解包前校验路径、清单、体积和兼容声明，拒绝越界路径与逃逸链接；离线包携带所需知识文件，不携带 Cookie、密钥或业务运行数据。
- 包 ID／版本与挂载名分开；挂载名全局唯一，冲突直接提示。DSH 技能目录的同名优先规则不能代替宿主唯一性检查。
- 已安装版本内容不可原地覆盖；升级先校验并准备新版本，成功后切换。失败保持旧版本；用户积累与可分发内容分开存储。
- 一个运行任务固定网站、包版本和挂载快照。取消挂载／升级作用于新任务，当前任务使用原快照；需要立即撤销时停止当前任务。恢复任务需重观察并重新校验兼容性，不重放旧确认。
- 模型只先看到当前网站技能摘要，按需加载正文与附件。新任务刷新技能目录，旧对话中的知识不能恢复已撤销的宿主执行权限。
- 增加已验证只读流程执行入口：按明确参数完成菜单进入、筛选、查询、分页及结果读取，减少逐步模型往返；每一步检查页面和停止信号，限制步数／耗时，处理现有工具超时边界。
- 包保存语义定位规则与页面条件，执行时解析成当次元素引用；不得跨观察复用 `e0` 等临时编号。
- 查询范围内的填写只有在确认不会自动保存时才自动执行。写入仍使用宿主确认；自动保存控件在首次写入前确认。首版不新增复杂写入流程编排。

退出条件：一个包完成安装、挂载、执行、取消挂载、升级、失败保留旧版；重复使用不需要新增 ERP 专属产品代码。

### 3. 外部制作样例、功能验收与 Alpha 交付

- 以已授权森果页面的一个菜单域为首例，外部高能力 AI 勘察纯查询入口，产出 Skill、知识附件、一个可参数化查询流程及适用／结果判据；真实数据与身份不进入分发包。
- 同一普通模型分别执行无包、有包及再次复用任务。检查结果正确、确认次数、模型／工具调用、观察次数和耗时；人工等待单列，不以一次耗时承诺普遍提速。
- 用本地夹具的小幅页面变化验证失效识别；第二个结构不同的夹具通过另一个包接入，宿主不增加业务分支。
- 本地承担主要回归；CI 跑确定性检查及 macOS DMG 构建、复制到仓库外后的 DSH／Skill 加载和启动冒烟，避免开发依赖掩盖漏打包。
- 提供单一 arm64 DMG、可导入的脱敏样例 ZIP、简短配置说明和证据。版本号在交付时确定。

退出条件：功能闭环成立，样例只读流程零确认，重复执行的模型调用较无包基线减少；若没有收益，记录原因并调整，不用夸大效果代替验收。

## 最小验收集

| 方面     | 判据                                                                          |
| -------- | ----------------------------------------------------------------------------- |
| 原生复用 | 实际加载原生 Skill，摘要／正文／附件按需访问；仅当前网站可见                  |
| 生命周期 | 重名拒绝、重启恢复、卸载影响新任务、运行任务固定版本、升级失败保留旧版        |
| 执行边界 | 查询不确认；写入确认前不执行；自动保存先确认；未知暂停；停止撤销后续步骤      |
| 页面变化 | 定位缺失、歧义、页面不匹配均停止复用，重新观察；不盲目重复提交                |
| 结果     | 查询返回当前页面证据；输入变化不代表写入成功；原有写入待核对规则保留          |
| 简单提效 | 一个真实菜单域、同一普通模型、同一目标的小样本对比；不做大规模效果评测        |
| 分发     | 一个 arm64 DMG 和一个知识 ZIP；安装后不依赖开发仓库、系统 pnpm 或预置测试身份 |

## 实施方式

使用一个实现 PR，按以上三阶段提交可审阅变更。先验证再固化接口，在既有模块边界增加必要契约；仅按接入需要拆分宿主工具路由，不做全仓重构。

AI 完成实现、外部样例制作、测试、文档与 PR／Issue 维护；人集中审阅本规格、确认策略和真实结果。真实写入沿用先授权对象、确认后执行并恢复的约束，不因本轮查询提速而扩大写入范围。
