# M2：DSH 插件工作台与查询提速

状态：**产品路线已于 2026-09-08 获用户同意；具体开发方案已实施至本地功能验证，预览交付继续推进。** 基于 alpha.2 的本地使用反馈推进，不推定所有 M1 真实写入已验收。决策见 [ADR-0006](../decisions/0006-trusted-dsh-plugins.md)，执行跟踪见 [Epic #9](https://github.com/GuoMonth/dsh-deskwork/issues/9)。

## 目标与边界

完成「外部高能力 AI 熟悉 ERP 菜单域 → 制作并发布标准 DSH 插件 → 用户从插件市场主动安装并信任 → 挂载到网站 → 普通模型调用知识与工具连续查询」闭环。

- 直接复用 DSH 插件格式、依赖、配置与生命周期。Skill、知识关系、可执行工具和流程均可作为插件内容；不另造资产包协议，不保留 ZIP 导入或离线备用路线。
- 市场发现和安装是 M2 核心交付。优先接入既有社区市场，不自建插件注册中心；开放标准插件安装，不限定为内置 ERP 白名单。这是开源迭代项目，不承诺插件、DSH 历史版本或未来版本的兼容性，不建设认证、兼容矩阵或自动适配层。
- 用户主动安装并信任本地扩展。安装前展示来源、包名、版本和本地代码执行提示；能力说明不冒充操作系统权限隔离。业务写入确认与安装信任是两件事。
- 经 Deskwork 浏览器接口执行的已验证查询直接推进，业务写入前确认，影响未知时暂停。第三方插件自身的文件、网络或进程操作不受这套浏览器确认机制完整约束。
- 网站仍只需网址即可接入，插件是可选增强；业务名称、选择器和字段不进入通用宿主。包不携带 Cookie、密钥和用户业务数据。
- 保留 Electron、React、严格 TypeScript、Node/npm、现有 DSH 独立运行时和桌面热重载。从当前 DSH `0.1.2-rc.1` 起步；为打通功能可以直接升级并锁定本轮版本，不维护旧版分支或多版本适配。
- PC 优先，仅发布 macOS Apple Silicon DMG。只做必要功能验证与小样本调用比较，不做大型效果评测。

## 阶段一：市场安装与原生插件加载（#10）

直接交付可操作的插件管理界面和真实安装链路，集成探针与实现放在同一个工作步骤内，不单独建设兼容验证项目。

1. 选定一个既有市场，优先接入 [dsh-market](https://github.com/dsh-market/dsh-market)，复用目录来源和 DSH 安装机制。先用一个最小标准插件跑通当前 SDK 的 bundle/patch、Skill 与工具加载，再立即接入桌面。市场依赖与当前 profile 有冲突时，修改最小适配或升级本轮依赖；不做多市场抽象。
2. 默认在 Deskwork 内做精简「插件」页面：市场搜索／安装、已安装列表、版本、启停、更新、卸载及运行错误；如现有管理组件可直接复用则复用，不搬入完整 DSH Web 工作台。安装时确认来源与本地扩展信任。
3. 在 userData 中管理插件安装环境和配置，使安装与 DSH 实际加载指向同一份依赖；应用安装目录保持只读。复用 DSH／包管理器能力，不另造包格式。
4. 升级由用户触发。更改前保存可用环境，失败保留原环境与错误信息；先按本轮实际用到的安装／加载失败路径实现，不建设通用依赖求解、兼容扫描或自动修复系统。
5. 完成启停、更新、卸载和重启恢复。第三方插件安装或加载失败直接显示原因，按实际需求修复；不为市场内所有插件预装额外程序或增加兼容分支。

完成标志：用户在热重载客户端从市场安装一个标准插件，真实 DSH 可以调用其 Skill／工具，管理生命周期可操作。运行依赖的最终 DMG 验证集中在第三步，不阻塞第二步业务开发。

## 阶段二：网站挂载、宿主接口与连续查询（#11）

依赖阶段一确定的加载与安装接口；查询策略的回归用例可提前准备。

1. 复用包标识／版本和 DSH 配置实例，增加宿主全局唯一挂载名及网站绑定。安装、挂载、取消挂载和卸载分别表达；取消挂载不删除网站或登录身份。面向普通插件保留其原生能力，面向网站插件提供任务绑定上下文。
2. 提供最小、版本明确的 Deskwork 插件接口：目标网站／页面上下文、观察与定位、动作、结果读取、进度和停止。边界接收 `unknown` 并校验，不把 Electron 对象或登录凭据作为公共接口返回；这只是接口契约，不是对本地插件的安全隔离。
3. 原生 Skill 组件管理摘要、正文与附件的按需加载；网站挂载用于匹配任务与可见能力。插件可使用可执行代码组织流程，无需改写为宿主专用声明式格式。避免默认把所有插件知识塞进每次模型请求。
4. 每个运行任务保持固定目标与已加载插件版本。升级、取消挂载或卸载若影响运行任务，先等待结束或显式停止，再更改环境；必要时重启 DSH。M2 不要求运行中热替换或多版本并发调度。恢复任务重新观察并校验，不重放旧确认。
5. 将「是否需要确认」和「是否存在待核对写入」分开。已验证只读导航、筛选和查询连续执行；写入与自动保存首次发生前确认，未知影响暂停。普通按钮名称或模型声明不能单独作为只读证明；插件提供适用条件和动作语义，样例以实测支撑。
6. 通过宿主接口执行时，保留任务／页面／动作绑定、确认失效、停止撤销后续步骤及写入结果核对。插件直接访问网络的行为属于安装信任范围，界面与文档不得声称它也被统一写入拦截。
7. 支持插件工具用代码完成有界的多步查询，减少模型往返；每步检查停止和页面条件，限制步数／耗时。语义定位保存在插件，执行时解析当次元素引用；缺失、歧义或页面不匹配时重新观察或暂停。

退出条件：同一宿主接口支持两个结构不同的夹具插件，不增加 ERP 专属代码；挂载名冲突拒绝、网站绑定、停止和生命周期生效；只读直行、写入确认、未知暂停、保存失败不能宣布成功均有功能证据。

## 阶段三：发布 ERP 插件并交付 Alpha（#12）

1. 高能力 AI 在外部熟悉一个已授权的森果查询菜单域，制作标准 DSH 插件：原生 Skill、页面／业务关系知识、输入输出和结果判据、一个可参数化的查询工具。知识以可检索文件组织即可，不预建图数据库或自动学习平台。
2. 插件单独版本化并公开发布，仅记录实际测试的 DSH、Deskwork 和插件版本；按选定市场规则完成实际收录。npm／GitHub 发布不等于市场已可发现，必须从市场重新安装验证。
3. 普通模型执行同一查询的无插件、有插件与再次使用三个小样本；确认结果正确、查询无多余确认，记录模型／工具调用与耗时。若没有减少往返则修正该流程；不设通用提速比例，不扩大效果测试。
4. 用夹具验证页面改变后的失效识别及第二种页面结构；真实网站只进行已授权操作，写入场景保留原授权、核对和恢复要求。
5. 本地热重载承担功能、PC UI 和交互调试；CI 执行确定性检查及 macOS arm64 构建。随应用提供本轮安装链路与样例所需的运行依赖。打包后复制到仓库外，验证市场安装、真实 DSH 加载、查询、退出与重启；真实模型和用户 Mac 的证据分开记录。
6. 交付单一 arm64 DMG、公开插件／市场链接、精简安装说明与限制。现有临时签名和未公证边界保持，版本号在发布时确定。

退出条件：用户可以安装客户端，从市场找到并安装样例插件，唯一命名挂载网站，完成查询及再次复用；不依赖开发仓库或预置测试身份。

## 最小验收集

| 范围       | 必须确认的功能                                                       |
| ---------- | -------------------------------------------------------------------- |
| 市场       | 真实来源发现、主动信任安装、失败提示；标准插件加载并能调用           |
| 生命周期   | 重名拒绝、挂载／取消、启停、升级失败保留旧环境、卸载与重启恢复       |
| 运行任务   | 目标与版本不被静默替换；影响任务的变更先停止或等待；恢复重观察       |
| 查询与写入 | 已验证查询零确认；宿主介导写入先确认；自动保存和未知控件单独处理     |
| 异常与结果 | 页面变化不盲用旧引用、停止无后续宿主动作、写入响应丢失不重提且待核对 |
| 通用性     | 两种结构通过插件表达业务差异；宿主不新增 ERP 分支                    |
| 分发       | 市场可安装公开样例；仓库外的 arm64 DMG 功能通过；实测环境分别报告    |

本轮不建设 ZIP 资产路线、自有市场、针对不可信插件的系统沙箱、自动生成／修复／晋升平台、复杂流程编辑器、多平台分发或大规模性能平台。不做任何兼容性承诺；记录本轮测试版本和已知问题即可。

## 代码落点与推进方式

以下是开发时的职责划分，精确类型由最小接入确定，不提前建设框架。

| 落点                                               | 本轮修改                                                                     |
| -------------------------------------------------- | ---------------------------------------------------------------------------- |
| `src/host/plugin-manager.ts`（新增）               | 调用安装机制、维护安装状态与挂载配置、串行执行生命周期变更；先服务一个市场   |
| `src/runtime/dsh-runtime.ts`                       | 从已安装插件环境启动 DSH，组合配置、加载原生能力；停止任务后重新加载         |
| `src/runtime/tool-server.ts`、`tool-contract.ts`   | 在现有私有桥上提供插件所需的目标上下文、浏览器调用、停止和结构化结果         |
| `src/core/contracts.ts`、`task-controller.ts`      | 最小插件／挂载类型；区分查询确认与写入核对，维持任务目标和取消规则           |
| `src/host/main.ts`、`state-store.ts`、`preload.ts` | 接线、持久化和 IPC 边界校验；按需要抽出模块，避免继续堆大 main               |
| `src/ui/`                                          | 新增精简插件管理界面与网站挂载操作，沿用现有 Token；保留 Copilot／Agent 交互 |
| 独立 ERP 插件包                                    | Skill、知识附件、语义定位和查询工具；独立发布，业务代码不进入宿主启动路径    |

一个实现 PR，三个大提交阶段：**装得上 → 用得快 → 发得出**。按 #10 → #11 → #12 连续推进，最小探针验证后直接做完该阶段界面和链路，不拆成大量只调查不交付的小任务。阶段产物可演示，AI 同步更新进度，不把每阶段结束设为必须等待人工批准的关卡。

本地热重载贯穿前两步；行为变化保留必要回归，优先复用现有夹具。整轮末执行确定性检查，第三步只对一个真实菜单流程做功能与少量调用记录，并构建一个 arm64 DMG。失败按当前实际问题修复，不扩大测试矩阵。源代码类型与配置版本用于开发一致性，不代表稳定 API 或向后兼容承诺。

AI 负责实现、插件制作、功能测试和记录维护；人集中审核必要取舍和真实结果。当前实现与验证结果见 [M2 实验记录](../experiments/2026-09-08-m2-plugins.md)，未完成交付项在 Issue #12 跟踪。

长期边界见[插件宿主设计](../design/plugin-host.md)；技术未知与判据见 [H-009](../hypotheses/h009-dsh-plugin-host.md)。只把真实执行结果写入实验记录，不以当前规划作为通过证明。
