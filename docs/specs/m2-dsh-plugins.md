# M2：DSH 插件工作台与查询提速

状态：**产品路线已于 2026-09-08 获用户同意；以下为具体开发计划，尚未实施。** 基于 alpha.2 的本地使用反馈推进，不推定所有 M1 真实写入已验收。决策见 [ADR-0006](../decisions/0006-trusted-dsh-plugins.md)，执行跟踪见 [Epic #9](https://github.com/GuoMonth/dsh-deskwork/issues/9)。

## 目标与边界

完成「外部高能力 AI 熟悉 ERP 菜单域 → 制作并发布标准 DSH 插件 → 用户从插件市场主动安装并信任 → 挂载到网站 → 普通模型调用知识与工具连续查询」闭环。

- 直接复用 DSH 插件格式、依赖、配置与生命周期。Skill、知识关系、可执行工具和流程均可作为插件内容；不另造资产包协议，不保留 ZIP 导入或离线备用路线。
- 市场发现和安装是 M2 核心交付。优先接入既有社区市场，不自建插件注册中心；开放标准插件安装，不限定为内置 ERP 白名单。插件兼容性以实际宿主、版本和依赖为准。
- 用户主动安装并信任本地扩展。安装前展示来源、包名、版本和本地代码执行提示；能力说明不冒充操作系统权限隔离。业务写入确认与安装信任是两件事。
- 经 Deskwork 浏览器接口执行的已验证查询直接推进，业务写入前确认，影响未知时暂停。第三方插件自身的文件、网络或进程操作不受这套浏览器确认机制完整约束。
- 网站仍只需网址即可接入，插件是可选增强；业务名称、选择器和字段不进入通用宿主。包不携带 Cookie、密钥和用户业务数据。
- 保留 Electron、React、严格 TypeScript、Node/npm、现有 DSH 独立运行时和桌面热重载。DSH 当前固定 `0.1.2-rc.1`；升级必须由兼容验证驱动。
- PC 优先，仅发布 macOS Apple Silicon DMG。只做必要功能验证与小样本调用比较，不做大型效果评测。

## 阶段一：市场安装与原生插件加载（#10）

先验证最小插件在当前 SDK 运行时与安装包中的真实可用性，再确定界面与适配方式。

1. 固定候选市场及源码版本，验证目录发现、安装来源、标准 DSH bundle/patch、依赖解析和原生 Skill／工具加载。优先评估 [dsh-market](https://github.com/dsh-market/dsh-market)；它面向 DSH Web，不能把 Web 演示视为桌面验证。
2. 在保留 Deskwork 外壳的前提下，选择复用市场服务或嵌入其管理界面的最小方案。验证 Web 组件依赖、独立 SDK profile、启停方式与目录服务接口；缺口写入实验结论，不静默取消市场目标或另建注册中心。
3. 插件安装目录、配置与锁文件放入用户数据目录，应用安装目录只读。管理安装环境和运行时实际加载环境的一致性，避免依赖从开发仓库误解析成功。
4. 复用 DSH 安装链路，验证并随应用提供所需包管理运行依赖；支持范围内的插件安装不要求用户预装 Node、pnpm 或编译工具。原生模块、额外程序或 Web 专属组件按实测标明前置条件与兼容状态，不承诺全市场通用。
5. 提供「插件」入口：市场浏览／搜索、来源与版本、主动信任安装、进度和错误、已安装列表、启停、升级与卸载。更新由用户触发，不自动执行无人审核的新版本；首次信任说明涵盖所选来源的本地扩展执行。
6. 依赖准备失败保留原可用环境；升级前保存配置和锁定版本，在候选安装环境验证后切换。加载失败回退到旧环境；这不承诺撤销插件已产生的业务或文件副作用。

退出条件：真实 DSH 进程加载一个标准 Skill／工具插件；市场发现→安装→调用→禁用→启用→升级→卸载→重启成立。至少一次验证从仓库外启动的打包应用安装插件，不借用系统包管理器。兼容缺口、选定市场及适配依据有记录。

## 阶段二：网站挂载、宿主接口与连续查询（#11）

依赖阶段一确定的加载与安装接口；查询策略的回归用例可提前准备。

1. 复用包标识／版本和 DSH 配置实例，增加宿主全局唯一挂载名及网站绑定。安装、挂载、取消挂载和卸载分别表达；取消挂载不删除网站或登录身份。面向普通插件保留其原生能力，面向网站插件提供任务绑定上下文。
2. 提供最小、版本明确的 Deskwork 插件接口：目标网站／页面上下文、观察与定位、动作、结果读取、进度和停止。边界接收 `unknown` 并校验，不把 Electron 对象或登录凭据作为公共接口返回；这只是接口契约，不是对本地插件的安全隔离。
3. 原生 Skill 组件管理摘要、正文与附件的按需加载；网站挂载用于匹配任务与可见能力。插件可使用可执行代码组织流程，无需改写为宿主专用声明式格式。避免默认把所有插件知识塞进每次模型请求。
4. 每个运行任务保持固定目标与已加载插件版本。升级、取消挂载或卸载若影响运行任务，先等待结束或显式停止，再更改环境；必要时重启 DSH。M2 不要求运行中热替换或多版本并发调度。恢复任务重新观察并校验，不重放旧确认。
5. 将「是否需要确认」和「是否存在待核对写入」分开。已验证只读导航、筛选和查询连续执行；写入与自动保存首次发生前确认，未知影响暂停。普通按钮名称或模型声明不能单独作为只读证明；插件提供适用条件和动作语义，样例以实测支撑。
6. 通过宿主接口执行时，保留任务／页面／动作绑定、确认失效、停止撤销后续步骤及写入结果核对。插件直接访问网络的行为属于安装信任范围，界面与文档不得声称它也被统一写入拦截。
7. 支持插件工具用代码完成有界的多步查询，减少模型往返；每步检查停止和页面条件，限制步数／耗时。语义定位保存在插件，执行时解析当次元素引用；缺失、歧义或页面不匹配时重新观察或暂停。

退出条件：同一宿主接口支持两个结构不同的夹具插件，不增加 ERP 专属代码；挂载名冲突拒绝、网站绑定、停止和生命周期生效；只读直行、写入确认、未知暂停、保存失败不能宣布成功均有功能证据。

## 阶段三：发布 ERP 插件并交付 Alpha（#12）

1. 高能力 AI 在外部熟悉一个已授权的森果查询菜单域，制作标准 DSH 插件：原生 Skill、页面／业务关系知识、输入输出和结果判据、一个可参数化的查询工具。知识以可检索文件组织即可，不预建图数据库或自动学习平台。
2. 插件单独版本化并公开发布，声明 DSH 和 Deskwork 接口兼容范围；按选定市场规则完成实际收录。npm／GitHub 发布不等于市场已可发现，必须从市场重新安装验证。
3. 普通模型执行同一查询的无插件、有插件与再次使用三个小样本；确认结果正确、查询无多余确认，记录模型／工具调用与耗时。若没有减少往返则修正该流程；不设通用提速比例，不扩大效果测试。
4. 用夹具验证页面改变后的失效识别及第二种页面结构；真实网站只进行已授权操作，写入场景保留原授权、核对和恢复要求。
5. 本地热重载承担功能、PC UI 和交互调试；CI 执行确定性检查及 macOS arm64 构建。打包后复制到仓库外，验证市场安装、真实 DSH 加载、查询、退出与重启；真实模型和用户 Mac 的证据分开记录。
6. 交付单一 arm64 DMG、公开插件／市场链接、精简安装说明与限制。现有临时签名和未公证边界保持，版本号在发布时确定。

退出条件：用户可以安装客户端，从市场找到并安装样例插件，唯一命名挂载网站，完成查询及再次复用；不依赖开发仓库或预置测试身份。

## 最小验收集

| 范围       | 必须确认的功能                                                       |
| ---------- | -------------------------------------------------------------------- |
| 市场       | 真实来源发现、主动信任安装、失败提示；标准插件加载并能调用           |
| 生命周期   | 重名拒绝、挂载／取消、启停、升级失败保留旧环境、卸载与重启恢复       |
| 运行任务   | 目标与版本不被静默替换；影响任务的变更先停止或等待；恢复重观察       |
| 查询与写入 | 已验证查询零确认；宿主介导写入先确认；自动保存和未知控件单独处理     |
| 异常与结果 | 页面变化不盲用旧引用、停止无后续宿主动作、写入响应丢失不重提且待核对 |
| 通用性     | 两种结构通过插件表达业务差异；宿主不新增 ERP 分支                    |
| 分发       | 市场可安装公开样例；仓库外的 arm64 DMG 功能通过；实测环境分别报告    |

本轮不建设 ZIP 资产路线、自有市场、针对不可信插件的系统沙箱、自动生成／修复／晋升平台、复杂流程编辑器、多平台分发或大规模性能平台。开放安装不代表所有 DSH 插件已认证兼容。

## 实施组织

规划在当前文档 PR 审阅，产品实现使用一个大 PR，按三个阶段提交可审阅变更。Issue #10 → #11 → #12 顺序推进，阶段退出判据通过后再扩大范围。AI 负责实现、插件制作、功能测试和记录维护；人集中审核视觉、必要取舍和真实结果。

长期边界见[插件宿主设计](../design/plugin-host.md)；技术未知与判据见 [H-009](../hypotheses/h009-dsh-plugin-host.md)。只把真实执行结果写入实验记录，不以当前规划作为通过证明。
