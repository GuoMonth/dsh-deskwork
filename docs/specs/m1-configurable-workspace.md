# M1：可配置的 ERP AI 工作台

状态：**范围纠偏审阅稿，等待产品负责人审阅实施范围。** 通用产品定位已经确认；本文替代原「森果档口批发工作台」规格。当前草稿代码尚含旧业务耦合，不代表新规格已经实现。任务进度见 [M1 Epic #3](https://github.com/GuoMonth/dsh-deskwork/issues/3) 与 [Roadmap](../roadmap.md)。

## 交付目标

用户把每天使用的网站放进 Deskwork，原样登录和使用，再通过旁边的 DSH 对话让 AI 协助操作。交付中文、单用户、macOS Apple Silicon 预览版。

**添加网址 → 打开固定标签 → 用户登录 → 对话读取与操作当前网站 → 必要时确认提交 → 核对结果。**

换一个 ERP，只需修改配置。产品不要求开发者先编写该 ERP 的连接器、字段映射或业务模块。森果商户后台仅作为可选测试样例，不定义产品导航、业务对象或验收前置条件。

## 用户看到的结构

- 一个网址配置项就是一个工作区入口，以一个固定标签呈现；配置两个网址就有两个固定标签。M1 不再增加「系统连接 → Workspace → 业务模块」等用户层级。
- 首次启动显示添加网址的空状态；最少只填网址，名称可选。用户可添加、编辑、移除入口，重启恢复配置。没有配置时不自动打开森果。
- 网站保留自己的页面、样式和导航。页面跳转和登录弹窗属于该入口的浏览上下文，不自动新增持久配置；移除配置不执行网站里的业务删除。
- 应用内部管理稳定的入口标识和持久会话。用户无需填写 host、partition、sessionId 或 profileId。默认各入口身份隔离，同一入口内的登录跳转继续使用其会话；高级共享会话配置后续再做。
- 外壳采用已定的浅色 Token 和 VS Code 式区域分工。名称、地址和网站图标来自配置或网站，工具入口使用通用任务语言。
- Copilot 显示网站与右侧对话；轻量 Agent 将对话展开，保留目标入口并提供「查看页面」。两种视图使用同一任务和浏览器会话。

## M1 能力边界

| 能力       | 本轮范围                                                                       |
| ---------- | ------------------------------------------------------------------------------ |
| 配置与浏览 | 界面添加网址、固定标签、手动登录、会话持久化、切换与返回页面                   |
| DSH 对话   | 真实运行时及模型连接，流式响应、工具步骤、停止、人工接手与恢复                 |
| 浏览器操作 | 观察页面、定位元素、导航、点击、填写、滚动与结果读取；绑定本应用拥有的目标页面 |
| 执行控制   | 任务不随标签切换漂移；同一会话自动操作串行；提交前确认、停止后撤销后续工具执行 |
| 结果反馈   | 区分实际观察、模型解释和结果待核对；运行记录本地保留，重启后恢复必要上下文     |
| 交付       | 自带运行依赖的 macOS arm64 未签名／未公证预览安装包                            |

确认围绕「哪个网站／页面、将执行什么动作、哪些输入或对象受影响」组织，不把店铺、商品、金额等字段写成通用任务协议的必填项。读取、导航与填写可连续进行；提交动作先提议，再由宿主校验确认和目标状态后执行。无法判断动作影响或页面状态时转交用户。不能仅靠模型把任意点击标注为导航就绕过确认；通用动作边界的可行性必须通过 [H-008](../hypotheses/h008-configured-site-operation.md) 验证。

停止不能撤回已经发出的请求。有副作用的动作超时、断连或进程退出时，保留「结果待核对」，重新观察实际状态；不能自动重复提交或仅凭模型文字宣布成功。不同网站的结果判据由当次页面观察与任务形成，无须预装业务 schema；无法核对时明确交给用户。

## 验收标准

| 编号              | 可观察的通过条件                                                                                                                                                            |
| ----------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A1 配置即接入     | 从空状态依次配置 1、2、3 个网址，固定标签数与顺序匹配；编辑、移除、重启后保持一致。接入第二个不同网站仅改配置，不新增源码、选择器文件或业务适配。                           |
| A2 原样浏览与身份 | 两个不同来源的测试站点独立登录，重启保留各自状态；同源双入口也验证身份隔离。页面内跳转、登录弹窗仍归属原入口，网站没有宿主桥接权限；外壳不重绘网站业务 UI。                 |
| A3 共享任务       | Copilot／Agent、标签切换和面板缩放保持上下文；任务只操作原绑定入口。停止后没有后续自动动作，接手后恢复先重新观察。                                                          |
| A4 通用操作闭环   | 同一套浏览器工具在两个结构不同的站点完成读取、导航、填写、确认提交与结果核对，不要求商品／店铺字段。至少一条测试把真实 DSH 进程、模型工具调用和真实 Electron 页面串在一起。 |
| A5 异常与确认     | 确认前无提交；页面／身份／输入变化使旧确认失效；覆盖登录过期、目标关闭、用户接手、弹窗目标定位，以及保存响应丢失后不重复提交。无法识别状态时停止并说明原因。                |
| A6 实机交付       | 从 arm64 安装包启动自带 DSH，完成配置、登录、真实模型操作、退出与重启；在用户 Mac 单独验收。Linux、macOS CI、真实模型和真实网站证据分别报告。                               |

确定性回归使用两个结构不同、通过配置接入的本地网站；夹具只服务测试，不被产品当成内置业务模块。真实网站优先使用用户提供的森果样例，勘察与任务都通过通用能力完成。无测试账号时可以先验证公开页面；需要登录或写入的验收如实留待实测，不以开发森果适配器补齐。真实写入仅在获准测试对象上执行并恢复数据。

配置接入能力不等于所有 ERP 操作已经兼容。iframe、弹窗、SSO 或特殊控件的支持范围由实测报告说明；遇到缺口先评估通用浏览器能力，不能默认转向逐 ERP 手写产品模块。

## 三个连续步骤

1. **配置与外壳纠偏**：移除产品中的森果身份和业务假页面，实现最少配置与固定入口，提交空状态、多标签、Copilot／Agent 的可交互预览供视觉审阅。
2. **通用浏览器 Agent 闭环**：把业务专属工具与确认契约改为页面／动作边界，接入真实 DSH，完成双站点及异常回归。视觉审阅期间可推进独立的运行时与浏览器验证。
3. **实机验证与预览交付**：验证真实模型和配置网站，重新生成安装包，在用户 Mac 验收并提供结果、截图和限制。

## 明确后移

以下内容不是 M1 完成门槛：预装垂直业务技能、技能复用加速评测、自动学习／修复／晋升／回滚、业务 API 学习、通用 MCP 配置。保留已有实验作为后续证据，不为复用它们而扩大本轮产品范围。

Rust/Wasm、Bun/Deno、深色主题、多平台、自动更新和 Apple 签名公证继续后移。M1 不搭建插件市场、ERP 连接器框架或复杂的工作区层级。

人审阅本次范围、必要架构取舍、视觉和真实业务结果；AI 承担实现、测试、证据和 PR 维护。本轮对齐先更新文档与 GitHub 任务，不把未审阅的新计划直接当成已交付代码。
