# ADR-0001：证据驱动的开发基础

状态：接受；执行角色、检查频率与实验隔离政策由 [ADR-0002](0002-ai-owned-development.md) 更新。日期：2026-09-05。来源：项目发起人的开发规范要求。

## 选择

- 按原则、标准、设计、决策、假设与实验组织文档；不重复描述已经可从代码读出的实现。
- 第一方逻辑使用严格 TypeScript，Node.js 24 + npm 锁文件 + ESLint typed lint + Prettier；快速测试采用 Node 内置测试运行器。
- 当前 TypeScript 固定 6.0.3：调研时最新版为 7.0.2，但 typescript-eslint 8.69.0 声明支持 `<6.1.0`。先选兼容组合，不以最新版本为目标。
- Electron 44.2.0 仅作为 H-001 实验依赖。DSH 与 Browser Harness 尚未选定集成版本或加入产品依赖。
- 本地执行真实浏览器实验，PR CI 运行快速检查，手动 CI 可补跑浏览器实验。

## 理由与替代方案

单一语言、锁文件与统一命令降低人和 AI 的上下文成本。运行时输入仍需校验，编译不能替代集成实验。

暂不引入完整桌面脚手架、monorepo、UI 框架或复杂测试框架，因为当前目标是验证边界。暂不运行每次 PR 的多平台浏览器矩阵，因为本地算力充足且首个目标平台尚未确定。

## 后果与复议条件

需要维护工具兼容性和少量实验基础设施。产品开始实现或新增运行环境时复议构建与测试方式；不得从实验目录结构推导正式模块边界。

版本核对命令：`npm view typescript version`、`npm view typescript-eslint peerDependencies --json`。实际安装版本以仓库锁文件为准。
