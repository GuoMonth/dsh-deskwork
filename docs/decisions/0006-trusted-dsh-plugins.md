# ADR-0006：复用 DSH 插件生态，信任用户主动安装的本地扩展

状态：**接受**。日期：2026-09-08。

## 背景与决定

用户要求 ERP 菜单域知识与执行经验可发布、安装、挂载、取消和升级，并明确选择「用户主动安装并信任本地扩展」，将 DSH 插件及市场安装列为 M2 主线，取消 ZIP 路线。

采用标准 DSH 插件作为唯一扩展形态，复用生态格式、依赖和生命周期。插件可包含 Skill、知识附件及可执行工具；由外部高能力 AI 制作，通过既有市场发现和安装，Deskwork 作为桌面宿主提供网站绑定、唯一挂载名和浏览器接口。

## 理由与替代方案

共用插件生态能让作者只维护一种交付物，并直接使用其依赖和工具机制。原计划「数据型 ZIP + 受限流程 + 市场后移」增加平行协议，现撤回；不保留离线 ZIP 备用入口。自建市场与针对不可信插件的操作系统沙箱均不纳入 M2。

## 后果

- 安装前明确来源、版本及本地代码执行含义。用户信任扩展后允许其在本地运行，不将每次调用变成重复安装授权。
- Deskwork 的确认、停止和目标控制覆盖经过宿主接口的浏览器动作，不能承诺控制插件自身的一切网络、文件或进程行为。只读／写入描述是接口及插件的行为契约，不是系统权限强制限制。
- 保留升级失败回退、影响运行任务前停止、唯一挂载名和用户数据独立存放；无需 M2 建设运行中热替换。
- 开放安装与全生态兼容是不同承诺。DSH Web 依赖、SDK profile、包管理器与 arm64 依赖必须实测；兼容缺口不会自动把产品方向改回 ZIP。

## 证据与未决问题

路线与信任模型来自用户明确决策，不依赖技术实验批准。[DSH 安装实现](https://github.com/deepseek-ai/deepseek-harness/blob/master/apps/cli/src/plugin.ts)与[候选社区市场](https://github.com/dsh-market/dsh-market)提供调查入口；尚不能证明 Deskwork 安装闭环成立。具体市场适配和分发依赖由 [H-009](../hypotheses/h009-dsh-plugin-host.md)验证，实施以 [M2 规格](../specs/m2-dsh-plugins.md)为准。
