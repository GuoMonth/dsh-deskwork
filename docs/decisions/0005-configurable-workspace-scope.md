# ADR-0005：配置接入网站，业务知识不进入工作台内核

状态：**接受；用户已批准 M1 实施范围。** 2026-09-06 用户明确确认「各种 ERP 通过配置接入」，并要求先对齐工作计划再审核。

## 背景

首个测试网址被错误扩大为产品结构：外壳包含森果名称和商品入口，设计预览绘制合成 ERP，工具和确认协议要求店铺、商品及声明式字段适配。实际远端网站未被修改，但实现导致新网站仅配置网址还不能获得同样的操作能力。

## 选择

- 工作台只定义网址入口、浏览器会话、任务、对话和工具能力；网站自己的业务页面保持原样。
- 一条网址配置对应一个固定入口。最少输入为网址，名称可选；host、partition 和适配器不是用户必填概念。
- M1 使用通用浏览器观察与动作接口。业务对象信息来自当次任务和页面；不要求预装某个 ERP 的字段 schema 才能操作。
- 保留目标绑定、宿主确认、停止撤销与结果不明时核对的约束，重新验证它们在通用动作下的实现。具体协议在实验证据形成后确定，不以「模型自行判断」代替宿主边界。
- 森果只作为测试配置；旧商品流程作为夹具和实验参考。M1 不把真实森果字段适配、预装业务技能或技能加速作为完成门槛。
- 未来站点经验与技能属于可选能力，不能成为添加新网站的前置依赖。

本决策**替代 ADR-0004 中仅开放三个资料工具、只允许声明式字段适配、默认森果业务入口的产品范围选择**。[ADR-0004](0004-m1-desktop-integration.md) 的 Electron、DSH 进程／分发以及已有实验结论保留；它们不证明新的通用动作能力已经通过。

## 理由与替代方案

继续为森果完善连接器，会验证一条定制业务而非配置式产品；只去掉界面品牌又保留固定字段契约，也不能证明换网站即可操作。因此本轮同时纠正规格、外壳和执行边界，不引入连接器框架承接旧耦合。

保留 Electron + DSH + 宿主 CDP 基础，Browser Harness 继续作为候选适配实现；不因产品范围纠偏重做已经有证据的运行时和工具链。

## 后果与待验证

通用页面定位、动作确认与结果核对的覆盖范围仍需验证，见 [H-008](../hypotheses/h008-configured-site-operation.md)。两种结构不同的测试站点必须只通过配置接入，使用相同工具完成操作。未覆盖的网页控件或认证流程应记录限制，不能把失败隐藏成专属业务适配。

新规格见 [M1](../specs/m1-configurable-workspace.md)。通用实现与覆盖限制见 [本轮验证](../experiments/2026-09-06-configurable-mvp.md)；旧记录仅保留为历史证据。
