# 工作台设计

用户配置入口、在原网站登录，由 DSH 组织任务，Deskwork 提供页面与执行控制。界面行为和验收条件见 [M1 规格](../specs/m1-configurable-workspace.md)，交付状态见[路线图](../roadmap.md)。

## 职责

| 部分          | 负责什么                                               |
| ------------- | ------------------------------------------------------ |
| 网站入口      | 网址、名称及固定标签                                   |
| Electron 宿主 | 网站登录会话、页面、任务目标和本地存储                 |
| DSH 运行时    | 模型对话、原生会话、工具调用和审批                     |
| 浏览器接口    | 绑定页面的观察、动作、停止与结果核对                   |
| 业务插件      | 领域知识、适用条件和流程，见[插件宿主](plugin-host.md) |

网站保留自己的界面，外壳管理导航与对话。网站没有宿主桥接权限；模型只使用当前任务页面的工具。页面凭据不作为对话输入。

## 选择及扩展

当前采用 Electron、DSH 和宿主 CDP；Browser Harness 留作独立实验。会话恢复使用原生 DSH 日志。技术演进见[决策记录](../decisions/README.md)，最新集成证据见 [rc.2 验证](../experiments/2026-10-10-rc2-native-convergence.md)。

业务 API 和用户配置 MCP 是后续执行路径，需要分别验证身份和动作语义。它们沿用任务目标、确认和结果核对，不默认继承浏览器凭据。
