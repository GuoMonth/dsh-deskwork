# DSH Deskwork 设计说明

状态：产品设计提案。本文保留尚未实现的交互意图；技术结论以[假设登记](../hypotheses/README.md)和实验记录为准。实现后删除可由语义代码与测试表达的重复细节。

长期方向见[产品原则](../principles/product.md)：固定入口、技能积累、AI 组合、工具执行与可验证进化。

## 产品边界

DSH Deskwork 是面向 ERP 与业务操作的桌面工作台，负责组合业务浏览器、DSH 执行核心与工具连接。优先服务仍主要通过网页完成工作的业务人员。

首个版本目标是单用户桌面工作流。多租户云服务、集中调度、企业组织管理和广泛 ERP 适配不属于首个切片。

## 核心概念

| 概念       | 职责                                               |
| ---------- | -------------------------------------------------- |
| 工作区     | 保存系统连接、会话选择与任务入口                   |
| 系统连接   | 描述目标系统地址、允许的操作范围和可选 API 适配器  |
| 浏览器会话 | 管理用户在特定系统、账户下的登录状态与页面         |
| 任务       | 保存用户目标、选定连接、执行步骤、确认状态和结果   |
| DSH 运行时 | 承接对话与任务执行，通过宿主提供的工具访问业务能力 |
| MCP 连接   | 描述用户配置的服务、凭据引用和允许使用的工具       |

业务浏览器会话与 DSH 对话会话分别管理，通过任务上下文建立绑定。切换账户时不能静默把正在执行的任务转到另一个身份。

## Copilot 交互流程

1. 用户添加系统地址并打开标签页。
2. 用户自行完成登录，包括验证码、MFA 或 SSO 等交互。
3. 用户选择页面并发起任务，界面展示当前系统与账户信息（在可识别时）。
4. DSH 通过受控工具读取页面、执行操作并报告进度。
5. 提交等关键动作展示目标对象和变更内容，确认后执行。
6. 用户可暂停并接手。恢复前重新读取页面状态，避免基于旧页面继续操作。
7. 核对系统中的实际结果，返回结果摘要与必要的业务标识。

## Agent 交互流程

Agent 界面以任务对话为主，保留系统连接、身份状态和执行进度。任务可以使用已验证的 API 工具或用户配置的 MCP，两条路径不要求同时具备。

使用业务 API 时，由宿主执行层处理会话、CSRF 等系统要求。接口学习首先形成候选说明，再通过请求语义、授权范围、返回值与实际业务结果验证后，登记为可复用工具。不得仅因观察到一个网页请求就把它视为稳定接口。

MCP 路径使用独立配置的凭据和工具权限，不默认继承浏览器登录态。任务需要多个连接时，明确记录各工具使用的连接。

## 会话与工具边界

- 登录凭据与业务会话留在受控宿主层，工具调用使用会话引用；具体存储方案待技术验证。
- 不同系统和账户需要独立会话分区，跨站点 SSO 的兼容方式在原型阶段验证。
- 模型只接收完成任务所需的页面或业务数据；会话密钥不进入提示词、普通日志或导出的任务记录。
- 网页脚本不获得桌面宿主或 DSH 的任意执行权限，页面与宿主的桥接仅开放必要操作。
- 页面内容、接口返回与 MCP 输出不能改变用户授权范围。
- 浏览器操作与 API 调用共享任务的确认策略，切换工具路径不能绕过确认。

## 执行结果与恢复

任务至少区分：进行中、等待用户、已暂停、成功、失败、结果待核对、已取消。需要登录时进入等待用户状态。

对提交、审批等有副作用的动作，遇到超时或断连，应先查询实际状态；不能直接重试并假设前一次未生效。工具返回成功也需要结合业务响应与必要的结果回读判断。

首个切片应覆盖会话过期、页面变化、用户接手和提交后响应丢失这几种情况。

## 技术决策待办

| 决策             | 需要验证的问题                                                     |
| ---------------- | ------------------------------------------------------------------ |
| 桌面框架与浏览器 | 登录兼容性、标签页与分区会话、自动化接口、宿主隔离能力             |
| DSH 集成         | 上游来源与许可证、固定版本、启动退出、工具注册、任务取消、分发方式 |
| 会话与凭据存储   | 操作系统安全存储、会话持久化、注销与清理                           |
| API 适配器       | 首个 ERP 的认证方式、请求语义、工具输入输出与结果核对              |
| MCP              | 支持的传输方式、凭据配置、连接检查与工具权限                       |
| 发布平台         | 首个目标操作系统、安装包、签名与更新方式                           |

这些选择在原型验证后记录为具体决策。当前不承诺跨平台兼容或直接可用的 ERP 连接器。
